# LimeEye

Аналог savemod: юзербот на **Telethon** (работает от твоего личного аккаунта через
MTProto — это и есть та самая «автоматизация чатов», а не Bot API, поэтому он видит
удаление/правку чужих сообщений и умеет исполнять команды от твоего имени).

## Возможности

- **Save mod** — при удалении сообщения (своего или чужого) в чате, где вы состоите,
  бот шлёт вам в Избранное удалённый текст цитатой (HTML blockquote), с кликабельным
  юзернеймом собеседника (или ссылкой на профиль, если username не задан) и типом медиа.
- **Edit mod** — при изменении сообщения шлёт "было / стало", тоже цитатами, с тем же
  указанием юзернейма собеседника.
- **Точечные команды** (только от вашего аккаунта, чужие их не видят как команды):
  - `.mute [время]` — удалять все входящие сообщения в этом чате.
    Без аргумента — навсегда, либо `.mute 1h30m`, `.mute 2d`.
  - `.unmute` — снять мьют.
  - `.muted` — список замьюченных чатов.
  - `.clean` — очистить кэш сообщений чата.
  - `.ping`, `.help`

## Как это устроено технически

Telegram не присылает содержимое сообщения в событии "удалено" — только `id`.
Поэтому бот кэширует все проходящие сообщения (текст, тип медиа, отправитель) в
SQLite, а при получении события `MessageDeleted` / `MessageEdited` достаёт исходный
текст из кэша.

## Установка

```bash
pip install -r requirements.txt
```

### 1. Получить API_ID / API_HASH

На https://my.telegram.org → API development tools → создать приложение.

### 2. Сгенерировать сессию (один раз, локально, не на сервере)

```bash
python session_login.py
```

Введёт номер телефона, код из Telegram, пароль 2FA (если есть) и выведет
`SESSION_STRING`. **Это как пароль от аккаунта — никому не показывать и не
коммитить в git.**

### 3. Переменные окружения

```
API_ID=...
API_HASH=...
SESSION_STRING=...
LOG_CHAT=me          # необязательно, по умолчанию "me" (Избранное)
CMD_PREFIX=.         # необязательно
DB_PATH=limeeye.db   # необязательно
```

### 4. Запуск

```bash
python main.py
```

## Деплой на Railway (как и основной бот)

1. Тот же подход, что и у других твоих ботов: пушим репозиторий, в Railway добавляем
   переменные окружения из списка выше.
2. Обязательно подключите **volume** и укажите `DB_PATH` на файл внутри volume —
   иначе при рестарте контейнера кэш сообщений (а значит и save/edit mod) обнулится.
3. `Procfile` уже настроен на `worker: python main.py` (это не веб-процесс, а
   постоянно висящее соединение, так что не Web Service, а Worker в Railway).

## Важно знать

- Правила Telegram формально ограничивают автоматизацию **личного** аккаунта
  (в отличие от ботов через BotFather). Массовая рассылка/спам через юзербота может
  привести к временным ограничениям аккаунта — сам по себе этот функционал
  (сохранение своих же чатов, личные команды) низкорискованный, но об этом стоит знать.
- Если аккаунт используется в чужих группах — уточните, уместно ли логировать
  удалённые/изменённые сообщения других участников с точки зрения приватности
  в этих чатах.
