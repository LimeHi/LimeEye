# LimeEye

Аналог savemod, но БЕЗ телефона/сессии — работает через встроенную функцию
**Telegram Business → Чат-боты**. Это обычный бот через Bot API (токен от
BotFather), который Telegram подключает к твоему личному аккаунту напрямую.

## Возможности

- **Save mod** — при удалении сообщения (своего или собеседника) бот шлёт тебе
  в личку отчёт: текст удалённого сообщения цитатой (HTML blockquote), с
  кликабельным юзернеймом собеседника, и типом медиа, если оно было. Если это
  было фото/видео/голосовое/видеосообщение/файл/GIF/аудио — бот дополнительно
  пересылает сам файл (не только подпись "📷 Фото"), так что даже если
  собеседник удалит медиа из чата, у тебя останется копия.
- **Edit mod** — при изменении сообщения шлёт "было / стало", тоже цитатами.
- **Точечные команды** (пишутся прямо в чате с собеседником, только от тебя):
  - `.mute [время]` — удалять все входящие сообщения в этом чате.
    Без аргумента — навсегда, либо `.mute 1h30m`, `.mute 2d`.
  - `.unmute` — снять мьют.
  - `.muted` — список замьюченных чатов.
  - `.clean` — очистить кэш сообщений чата.
  - `.ping`, `.help`
- **🎛 Фишки** — раздел в личном чате с ботом (`/start` → «🎛 Фишки», либо команда
  `/features`) с дополнительными переключаемыми функциями:
  - **🕐 Часы в имени/фамилии** — кнопкой включаешь/выключаешь, выбираешь, куда
    ставить время: в имя или в фамилию. Пока фишка включена, бот раз в минуту
    сам обновляет выбранное поле текущим московским временем (`setBusinessAccountName`),
    а второе поле (имя или фамилия) оставляет как есть. При выключении бот
    возвращает исходное имя/фамилию. Требует право **«Изменение имени»**
    (`can_edit_name`) в настройках Business-подключения — без него часы не
    смогут обновляться, о чём бот предупредит в этом же меню.
  - **🔇 Сообщение о муте** — кнопкой включаешь/выключаешь. Пока фишка включена,
    каждый `.mute` дополнительно отправляет прямо в сам чат (не в личку) сообщение
    о том, что чат замьючен, с упоминанием бота (`@ИмяБота`) и кнопкой
    **«🔊 Размьютить»**, и закрепляет это сообщение в чате. `.unmute`, либо
    нажатие кнопки владельцем аккаунта, открепляет сообщение и меняет его текст на
    «мьют снят». Кнопку может нажать только владелец — собеседнику она ничего не
    даёт. Требует право **«Закрепление сообщений»** (`can_pin_messages`) в
    настройках Business-подключения — без него сообщение всё равно отправится,
    просто не закрепится.

Все ответы на команды и отчёты приходят тебе в личный чат с ботом (не в тот
чат, где была команда) — команда в самом чате с собеседником при этом удаляется
(если выдано право на удаление, см. ниже).

## Как это устроено технически

Telegram Bot API с 2024 года поддерживает подключение бота к личному аккаунту
через фичу Telegram Business: апдейты `business_connection`, `business_message`,
`edited_business_message`, `deleted_business_messages`. Никакого MTProto/сессии —
обычный Bot API + long polling.

Как и раньше, Telegram не присылает содержимое в событии "удалено" — только
`message_id`. Поэтому бот кэширует сообщения в SQLite и достаёт текст оттуда.

## Требования

- **Telegram Premium** на аккаунте, который будешь подключать (Business —
  часть Premium-подписки).
- Бот, созданный через @BotFather, с включённым **Business Mode**
  (`/mybots` → выбрать бота → Bot Settings → Business Mode → Turn on).

## Установка

```bash
pip install -r requirements.txt
```

### 1. Создать бота

Как обычно через @BotFather (`/newbot`), затем обязательно:
`/mybots` → выбрать бота → **Bot Settings** → **Business Mode** → **Turn on**.

### 2. Переменные окружения

```
BOT_TOKEN=...             # токен от BotFather
CMD_PREFIX=.               # необязательно
DB_PATH=limeeye.db         # необязательно
DB_ENCRYPTION_KEY=...      # обязательно, см. ниже
```

Сгенерировать `DB_ENCRYPTION_KEY`:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Бот шифрует в БД все чувствительные данные (текст сообщений, имена/юзернеймы,
file_id медиа, загаданное слово в виселице) симметричным шифрованием
(Fernet/AES). ID, даты и статусы остаются открытыми — по ним идёт поиск в БД.
Без `DB_ENCRYPTION_KEY` бот не запустится. **Ключ нельзя терять и нельзя
менять** на уже заполненной базе — старые записи станут нечитаемыми (это
защита от потери ключа, а не баг: бот не хранит запасной способ
расшифровки). Храните ключ так же бережно, как `BOT_TOKEN` — в переменных
окружения хостинга, не в репозитории.

### 3. Запуск

```bash
python main.py
```

### 4. Подключить бота к своему аккаунту

В Telegram (в приложении, не в этом чате с ботом!):
**Настройки → Telegram Business → Чат-боты** → ввести username бота → Добавить.

На экране подключения обязательно выдай боту права:
- **«Удаление сообщений»** (`can_delete_all_messages`) — без этого не будут
  работать `.mute`, `.clean` и автоудаление самой команды из чата. Без этого
  права save/edit-отчёты всё равно будут приходить, просто mute не сможет
  удалять сообщения.
- Можно ограничить, к каким чатам у бота есть доступ (все / определённые /
  все кроме исключённых) — это тоже настраивается на этом экране.
- **«Изменение имени»** (`can_edit_name`) — опционально, нужно только для фишки
  «🕐 Часы в имени/фамилии» (раздел «Фишки» в личном чате с ботом). Без него всё
  остальное продолжает работать как обычно.
- **«Закрепление сообщений»** (`can_pin_messages`) — опционально, нужно только для
  фишки «🔇 Сообщение о муте» (тоже в разделе «Фишки»). Без него сообщение о муте
  всё равно отправится в чат, просто не закрепится.

После подключения бот пришлёт тебе в личку подтверждение и напомнит, если
какого-то права не хватает.

## Деплой на Railway

1. Тот же подход, что и у других твоих ботов: пушим репозиторий, добавляем
   переменные окружения из списка выше.
2. Подключи **volume** и укажи `DB_PATH` на файл внутри volume — иначе при
   рестарте контейнера кэш сообщений (а значит и save/edit mod) обнулится.
3. `Procfile` уже настроен на `worker: python main.py` (постоянное соединение,
   long polling — Worker, не Web Service).

## Ограничения на заметку

- Business-чаты — это **личные (1-на-1) переписки**, привязанные к аккаунту;
  групповые чаты в эту функцию, как правило, не входят.
- `deleteBusinessMessages` требует права `can_delete_sent_messages` (для
  сообщений, отправленных самим ботом от твоего имени) или
  `can_delete_all_messages` (для удаления вообще любых сообщений в чате,
  включая написанные тобой лично с телефона и написанные собеседником) —
  для `.mute` нужен именно второй вариант.
- Если бот не будет отвечать/удалять — первым делом проверь, какие права
  реально выданы в Settings → Telegram Business → Чат-боты → твой бот.
